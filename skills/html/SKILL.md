# HTML

방금 나온 결과를 디자인된 HTML 문서 한 장으로 만든다. 역할이 나뉘어 있다. 너는 내용을 마크다운으로 정리하고 디자인(register)을 고르는 일만 하고,
배치·글꼴·색·번호는 `render_html` 도구가 모두 정한다. HTML 코드를 직접 쓰지 않는다. 문서는 외부 자원을 쓰지 않는 파일 한 장이라 내려받아 그대로 열 수 있다.

## 쓰지 않는 경우
- 배포할 웹사이트나 웹 앱을 만들어 달라는 요청.
- 이미지, 다이어그램, 로고 같은 그림.
- 분석 자체를 새로 하는 일. 먼저 분석을 끝내고, 그 결과를 문서로 만든다.
- 문서로 만들 내용이 대화에 아직 없으면 무엇을 만들지 묻는다. 내용을 지어내지 않는다.
- 후보가 여럿이면 어느 결과를 담는지 한 줄로 밝히고 진행한다. 예: "A 결과를 담았습니다. B를 원하시면 알려 주세요."

## 순서
1. 대화에 이미 나온 결과(조사 내용, 표, 수치, 인용)만 담는다. 새 수치를 만들지 않는다. 수치는 도구나 연구원이 준 값 그대로 쓰고, 원문 인용은 바꾸지 않는다. 출처와 검증 표시(확인됨·보도됨 등)는 남긴다.
2. `render_html(title=..., markdown=..., register=...)`을 한 번 호출한다. 오류가 돌아오면 메시지대로 고쳐 다시 부른다.
3. 결과의 `표시` 줄(`[[html:...]]`)을 최종 답변에 **그대로 한 줄로** 넣고, 한두 문장으로 무엇을 담았는지 적는다. 문서 내용을 답변에 다시 쓰지 않는다. 화면에 미리보기와 다운로드 버튼이 나오므로 따로 게시하거나 알리는 단계는 없다.

## register(디자인) 고르기
| 내용 | register |
|---|---|
| 근거 묶음, 비판 검토, 조사·수사 기록, 주장 검증 | `dossier` (짙은 녹색 + 주황, 굵은 제목 + 타자기체) |
| 보고서, 재무, 계획, 비교, 지표 | `ledger` (짙은 남색 + 금색, 명조 계열 제목) |
| 사용자가 지정함 | 그대로 따른다 |
| 앞서 같은 대화에서 문서를 만들었음 | 연속된 결과물이 똑같이 보이지 않게 다른 쪽을 고른다 |

## markdown 쓰는 법
| 쓰는 것 | 문서에서 |
|---|---|
| 첫 `##` 앞의 글 | 맨 위 요약 상자 |
| `## 제목` | 번호가 붙은 섹션 |
| `### 제목` | 섹션 안의 구분 제목 |
| `\| 표 \|` (구분줄 `\|---\|` 포함) | 표 |
| `- **머리말.** 설명` | 머리말이 굵은 목록 |
| `> 인용` | 강조 상자 |
| 빈 줄로 나눈 글 | 문단 |
| ```` ``` ```` 코드 | 고정폭 코드 상자 |

- 글 안에서는 `**굵게**`와 `` `코드` ``만 쓴다. HTML 태그는 글자 그대로 보인다.
- 본문에 제목(`# ...`)을 다시 쓰지 않는다. 제목은 `title` 인자에 넣는다.
- 표의 숫자도 글로 쓴다("12.3억"). 섹션은 40개, 표는 300줄까지다.
- **섹션 번호(01, 02…)는 앱이 문서 순서대로 붙인다.** 목록 항목에는 번호를 매기지 않는다. 진짜 순서가 있는 절차일 때만 `1.` 형식을 쓰고, 그 밖에는 `- **머리말.** 설명` 목록을 쓴다.
- 외부 이미지, 글꼴, 링크 같은 외부 자원은 쓸 수 없다(차단된다). 문서는 글, 표, 목록으로 구성한다.

예:

```
핵심을 한두 문장으로. **중앙값 12.3억**, 적자 확률 **18%**.

## 핵심 수치
| 항목 | 값 |
|---|---|
| 중앙값 | 12.3억 |
| 하위 5% | -4.1억 |

## 가장 큰 변수
- **수율 램프 기간.** 길수록 적자 확률이 커진다.

> 추진 여부 판단은 포함하지 않습니다.
```

## 지키는 것
- 사용자가 요구한 범위만 담는다. 추진 여부나 사업성 판단 같은 의견은 요청이 없으면 넣지 않는다.
- 문서에 새 register나 손으로 쓴 스타일을 끼워 넣지 않는다. 내용이 두 가지 디자인에 맞지 않으면 그대로 만들고, 아쉬운 점을 답변에 한 줄로 알린다.
