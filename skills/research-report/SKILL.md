# 연구 보고서

방금 나온 연구 결과를 아래 목차 그대로 보고서 한 편으로 정리한다. 목차의 이름과 순서는 바꾸지 않는다. 항목을 건너뛰지도 않는다. 내용이 없으면 "해당 없음"이라고 쓴다.

## 쓰지 않는 경우
- 짧은 질문에 답하는 일. 보고서 형식을 원한다는 말이 없으면 쓰지 않는다.
- 연구 자체를 새로 하는 일. 먼저 연구를 끝내고, 그 결과를 정리한다.
- 정리할 연구 결과가 대화에 아직 없으면 보고서를 쓰지 않는다. 조사나 분석이 필요한 요청이면 먼저 연구원에게 맡겨 결과를 받은 뒤에 쓰고,
  그것도 아니면 무엇을 정리할지 묻는다. 목차를 전부 "해당 없음"으로 채운 보고서는 내지 않는다. 내용을 지어내지 않는다.

## 쓰는 순서
작성은 아래 순서로 하고, 완성된 보고서는 목차 순서로 배열한다.
1. **결과**를 먼저 쓴다. 연구원이 준 수치·표·인용만 그대로 옮긴다. 새 수치를 만들지 않고, 코드를 실제로 실행해서 나온 값만 최종 수치로 쓴다.
2. **방법**을 쓴다. 어떤 자료를 어떻게 모으고 분석했는지, 어떤 연구원이 무엇을 했는지 적는다.
3. **한계**를 쓴다. 자료의 범위, 확인하지 못한 것, 가정한 것을 적는다. 사업상 가정은 자료 파일에 있는 것만 쓴다.
4. **배경**을 쓴다. 질문이 나온 이유와 조건을 적는다.
5. **결론**을 쓴다. 결과가 뒷받침하는 범위 안에서만 적고, 진행·중단 같은 판단은 내리지 않는다.
6. **요약**을 마지막에 쓴다. 결과와 결론의 핵심만 3~5문장으로 적고, 결과에 없는 내용은 넣지 않는다.

## 목차와 항목별 내용
| 항목 | 담을 내용 |
|---|---|
| 요약 | 핵심 결과와 결론, 3~5문장 |
| 배경 | 연구 질문, 조건, 왜 필요한지 |
| 방법 | 자료, 분석 절차, 사용한 도구 |
| 결과 | 수치, 표, 인용, 출처와 검증 표시 |
| 한계 | 범위, 미확인 사항, 가정 |
| 결론 | 결과가 뒷받침하는 정리 |

## 출력
- 보고서는 마크다운으로 쓴다. 각 항목은 `## 요약`, `## 배경`처럼 `##` 제목으로 둔다.
- 사용자가 HTML로 달라고 하면 `html` 스킬을 따라 `render_html`로 만든다. 그렇지 않으면 답변에 마크다운으로 바로 쓴다.
