COMMON AGENT

Common Agent 사용자 매뉴얼

Common Agent는 AI에게 도구를 쥐여 주고 일을 시켜 보는 앱입니다. 메모 도구로 대화하고, 외부 도구(MCP)를 붙이고, 연구책임자와 연구원 두 명에게 자료 분석을 맡길 수 있습니다. 이 문서는 화면 순서대로 따라가면 첫 결과까지 도착하도록 썼습니다.

1. 시작 전 준비

관리자에게 아래를 받아 두세요. 직접 켜서 쓰는 분은 설치·실행 안내(user-guide.md)를 먼저 보세요.

받을 것설명
앱 주소내 컴퓨터에서 쓰면 http://127.0.0.1:8770/, 공유 서버라면 관리자가 알려 준 https://… 주소입니다.
비밀번호공유 서버에서만 필요합니다. 브라우저가 로그인 창을 띄우면 사용자 이름은 아무거나 적고, 비밀번호 칸에 받은 값을 넣습니다.
연구에 쓸 자료 파일CSV · TXT · JSON, 파일당 2MB 이하, UTF-8로 저장한 것. 엑셀(.xlsx)은 CSV로 저장해서 올려야 합니다.

3. 도구 탭

화면 맨 위 파란 띠의 첫 번째 탭입니다. 여기서는 AI에게 메모 도구 4개를 주고 대화합니다.

3-1. 모델 연결

  1. 제공자에서 OpenRouter 또는 Ollama를 고릅니다.
  2. 모델 이름을 적습니다. Ollama는 도구 호출을 지원하는 모델이어야 합니다.
  3. Ollama를 골랐다면 Ollama API 주소가 나타납니다. 공유 서버에서는 localhost가 서버 자신을 뜻한다는 점에 유의하세요.
  4. 설정 저장을 누릅니다. 다음 요청부터 바로 적용됩니다.
참고OpenRouter 키는 화면에 입력하지 않습니다. 관리자가 서버에 설정해 둔 것을 씁니다.

3-2. 역할 지시문

AI가 요청을 처리할 때 따르는 기본 규칙입니다. 고친 뒤 저장, 되돌리려면 초기화를 누릅니다.

3-3. 스킬

오른쪽 아래 스킬 카드에는 AI가 필요할 때 읽는 지침이 모여 있습니다. 기본으로 html 스킬이 들어 있어서, 대화에서 "결과를 HTML로 만들어줘"라고 하면 디자인된 문서가 답 안에 미리보기로 나옵니다. 문서 위쪽의 다운로드를 누르면 파일로 받고, 아래 소스 보기로 HTML 소스를 볼 수 있습니다.

스킬을 직접 추가하려면 스킬 추가를 누르고 이름(영문 소문자·숫자·-), 설명, 지침을 적어 저장합니다. 저장하면 바로 다음 요청부터 적용됩니다. 설명에 언제 쓰는 스킬인지를 구체적으로 적어야 AI가 알맞은 때 읽습니다.

참고문서 미리보기 안에서는 스크립트가 실행되지 않습니다. 차트처럼 스크립트로 그리는 내용은 미리보기에서 비어 보일 수 있습니다. 스킬은 글만 담고 코드를 실행하지 않습니다.

3-4. 대화

요청을 입력하고 보내기를 누르면 AI가 알맞은 메모 도구를 골라 호출하고, 어떤 도구를 어떤 값으로 불렀는지가 답 아래에 펼쳐집니다.

도구하는 일
memo_tool_1키워드가 들어간 메모를 찾습니다. 낱말 하나라도 맞으면 걸립니다.
memo_tool_2새 메모를 저장합니다.
memo_tool_3키워드에 맞는 메모를 모두 삭제합니다. 되돌릴 수 없습니다.
memo_tool_4기존 메모의 한 문장만 바꿉니다. 대상이 여럿이거나 문장이 여러 번 나오면 고치지 않고 되묻습니다.

대화는 저장되어 다음 요청에 이어집니다(최근 30번). 새로 시작하려면 대화 초기화를 누르세요. 화면 오른쪽의 Context Window는 AI가 한 번에 기억할 수 있는 양 중 얼마를 썼는지 보여 줍니다.

주의삭제 도구는 "회의"처럼 흔한 낱말에 걸린 메모를 한꺼번에 지웁니다. 지우기 전에 먼저 검색으로 무엇이 걸리는지 확인하세요.

4. MCP 탭

MCP는 AI가 쓸 수 있는 외부 도구 묶음입니다. 법령 검색, 문서 검색 같은 서버를 붙이면 그 서버의 도구가 AI에게 주어집니다.

  1. MCP 서버 목록에서 쓰고 싶은 서버를 켭니다. 켜는 즉시 연결을 시도합니다.
  2. 목록에 없는 서버는 원격 서버 추가에서 이름과 주소를 넣고 추가를 누릅니다. 주소는 http:// 또는 https://로 시작해야 합니다. 서버가 인증 헤더를 요구하면 추가 헤더 칸에 한 줄에 하나씩 이름: 값으로 적습니다(예: Authorization: Bearer ${API_KEY}). 키는 값 자리에 직접 쓰지 말고 ${변수명}으로 적고, 실제 값은 관리자가 서버에 넣어 둡니다. 서버가 인증값을 헤더가 아니라 도구 인자(api_key 등)로 받는다면 고정 인자 칸에 api_key: ${변수명}으로 적으세요. 모든 도구 호출에 자동으로 들어가고 AI에게는 보이지 않습니다. 다른 곳에서 받은 mcpServers JSON이 있다면 JSON으로 추가 칸에 그대로 붙여 넣어도 됩니다(원격 서버만 가능).
  3. 오른쪽 사용 가능한 도구에서 서버가 가져온 도구를 확인합니다.
  4. 쓰고 싶지 않은 도구는 제외하면 제외된 도구로 옮겨지고, 언제든 되살릴 수 있습니다.
참고서버 하나가 연결에 실패해도 나머지는 그대로 쓰입니다. 실패한 이유는 화면 위쪽 빨간 띠에 나옵니다. 직접 추가한 서버만 삭제할 수 있고, 기본 목록의 서버는 연결을 끊는 것만 됩니다.

5. 에이전트 탭

이 앱의 핵심 화면입니다. 연구책임자(이 앱 자신)가 질문을 받아 두 명의 연구원에게 일을 나눠 맡깁니다.

역할하는 일쓸 수 있는 도구
연구책임자질문을 쪼개 연구원에게 맡기고, 돌아온 보고를 검토해 최종 답을 씁니다. 직접 조사하거나 계산하지 않습니다.맡기기 도구 2개뿐
자료조사 연구원어떤 분석 방법을 쓸지 설계합니다. 수치는 만들지 않습니다.웹 검색, 연결된 MCP 도구
실험수행 연구원연구 자료 파일을 읽고 값을 보고합니다.연구 자료 읽기뿐

두 연구원은 서로 직접 이야기하지 못합니다. 필요한 내용은 연구책임자가 지시문에 담아 전달합니다.

5-1. 에이전트 상태 (왼쪽 위)

세 역할이 켜져 있는지 보여 줍니다. 모두 시작 · 모두 종료로 연구원을 켜고 끌 수 있고, 새로 고침 버튼(↻)으로 상태를 다시 읽습니다. 연구를 시작하면 꺼져 있는 연구원은 자동으로 켜지므로 미리 켤 필요는 없습니다.

5-2. 연구 자료 (왼쪽 가운데)

  1. 파일 추가를 눌러 파일을 고릅니다(여러 개 가능).
  2. 같은 이름의 파일이 있으면 덮어쓸지 묻습니다.
  3. 올라간 파일은 목록에 이름과 크기로 나타납니다. 지우기(✕)를 누르면 되돌릴 수 없다는 확인창이 뜹니다.
참고실험수행 연구원은 파일 하나를 읽을 때 처음 6,000자까지만 받습니다. 아주 긴 표는 앞부분만 본다는 뜻이니, 핵심 값은 앞쪽에 두세요.

5-3. 연구 요청

  1. 입력창에 연구 질문을 씁니다. 조건과 자료 파일 이름을 구체적으로 적을수록 좋습니다.
  2. 연구 시작을 누릅니다. 몇 분 걸릴 수 있습니다.
  3. 아래 연구 진행에 연구책임자의 지시, 연구원의 보고, 연구원이 안에서 한 일이 순서대로 쌓입니다.
  4. 멈추고 싶으면 중지를 누릅니다. 이미 연구원에게 맡긴 일은 끝난 뒤에 멈추므로 바로 멈추지 않을 수 있습니다.
flowchart LR
    S1[대기 중] --> S2[연구원 켜는 중]
    S2 --> S3[연구 도는 중]
    S3 --> S4[끝남]
    S3 --> S5[중지 요청됨]
    S5 --> S4
    S4 -.->|이어서 물어보기| S3
    S4 -.->|새 연구| S1

5-4. 이어서 물어보기

연구가 끝나면 나타납니다. 앞선 연구를 기억한 채 "시행 횟수를 늘려서 다시" 같은 후속 질문을 할 수 있습니다. 완전히 새로 시작하려면 새 연구를 누르세요.

5-5. 연구원 지침

연구원마다 따르는 지침을 화면에서 고칠 수 있습니다. 지침 편집을 누르면 팝업이 열립니다. 연구원을 고르고 고친 뒤 저장을 누르면 다음에 일을 맡길 때부터 적용됩니다. 연구원을 다시 켤 필요는 없습니다. 기본값으로를 누르면 원래 지침으로 돌아갑니다.

주의기본 지침에는 "실행하지 않은 계산 결과를 지어내지 않는다", "사업 가정은 자료 파일의 값만 쓴다", "추진 여부를 판단하지 않는다" 같은 규칙이 들어 있습니다. 줄이거나 지우면 결과를 믿기 어려워질 수 있으니 무엇을 빼는지 확인하고 고치세요.

5-6. 역할 연결 상태

왼쪽 아래 접힌 영역을 펼치면 세 역할이 선으로 이어진 그림이 나옵니다. 연구원 사이에 "직접 통신 없음"이라고 적혀 있고, 연구 중에는 지시와 보고가 오가는 모습이 움직입니다.

6. 결과는 이렇게 만들어집니다

결과를 의심스럽게 느낄 때 어디를 봐야 하는지 알려 주는 그림입니다.

flowchart TD
    Q[내 질문] --> O[연구책임자]
    O -->|방법을 조사해 줘| R[자료조사 연구원]
    R -->|웹 검색과 MCP 도구| W[조사 결과]
    W --> O
    O -->|자료를 읽어 값을 알려 줘| X[실험수행 연구원]
    X -->|연구 자료 읽기| D[내 파일의 값]
    D --> O
    O --> V{수치가 서로 맞나}
    V -->|어긋남| X
    V -->|맞음| A[최종 보고]

그림 3. 질문에서 최종 보고까지

  • 숫자는 내 파일에서만 옵니다. 연구원은 사업 가정을 지어내지 않고 자료 파일에 적힌 값을 읽어 옵니다.
  • 연구책임자는 수치를 검토합니다. 서로 어긋나는 값이 돌아오면 그대로 쓰지 않고 실험수행 연구원에게 확인을 맡깁니다.
  • 보고에는 판단이 없습니다. 중앙값 · 하위 5% · 상위 5% · 민감도 순위까지만 다루고 추진 여부나 사업성은 말하지 않습니다.
  • 근거는 연구 진행 영역에 있습니다. 각 연구원의 보고를 펼치면 모델과 주고받은 내용과 도구 호출이 보입니다. 중요한 숫자는 펼쳐서 확인하는 습관을 들이세요.
중요현재 이 앱에서는 코드를 실행하는 기능이 꺼져 있습니다. 그래서 실험수행 연구원은 계산을 직접 돌리지 못하고, 필요한 코드와 입력을 보고하는 데 그칩니다. 질문에 "실제 파이썬 코드로 실행하세요"라고 적더라도 시뮬레이션 수치가 나오지 않는 것이 정상입니다. 숫자를 지어내서 채우는 것보다 이쪽이 안전한 동작입니다.

7. 접속과 권한

이 앱에는 사용자 계정이나 역할 구분이 없습니다. 접속하는 방법에 따라 비밀번호가 필요한지만 달라집니다.

접속 방법비밀번호할 수 있는 일
내 컴퓨터에서 127.0.0.1 또는 localhost필요 없음모든 화면과 기능
관리자가 알려 준 공유 주소필요함 (사용자 이름은 아무거나)모든 화면과 기능
공유 주소인데 관리자가 비밀번호를 설정하지 않음-접속 자체가 거부됨
  • 한 번에 한 사람이 쓰는 것을 전제로 만든 앱입니다. 여러 명이 같은 서버를 동시에 쓰면 대화 기록, 연구 자료, 연구원 지침을 서로 공유하고, 누군가의 연구가 도는 동안 다른 사람의 일부 요청은 기다립니다.
  • 화면에서 고친 설정(모델, 지시문, 연구원 지침, 추가한 MCP 서버)은 서버에 저장되어 접속한 모두에게 적용됩니다.

고장이 아닌데 실패처럼 보이는 것

  • 연구가 몇 분째 돕니다. 연구원 한 명의 작업이 길게는 10분까지 걸릴 수 있습니다. 연구 진행에 항목이 늘고 있으면 정상입니다.
  • 중지를 눌렀는데 바로 안 멈춥니다. 이미 맡긴 일이 끝나야 멈춥니다.
  • 답 아래에 "도구를 부르지 않았습니다"가 나옵니다. 오류가 아니라 AI가 도구가 필요 없다고 판단했다는 표시입니다. 도구를 쓰길 원했다면 요청에 무엇을 찾으라고 구체적으로 적거나, 도구(또는 스킬)의 설명이 "언제 쓰는지"를 말하고 있는지 확인하세요. 앞선 거절 답이 대화 기록에 남아 따라 하는 경우도 있으니 대화 초기화를 눌러 보세요.
  • HTML로 만들어 달랬는데 문서 대신 글만 나옵니다. AI가 html 스킬을 읽지 않은 경우입니다. "html 스킬로 HTML 문서를 만들어줘"처럼 다시 요청하세요. 작은 모델은 이럴 수 있습니다.
  • HTML 문서 미리보기가 비어 보이거나 차트가 없습니다. 미리보기 안에서는 스크립트가 실행되지 않습니다. 다운로드한 파일을 브라우저로 열어 보세요.
  • 실험수행 연구원이 수치를 못 냈다고 보고합니다. 위 6절의 경고대로 코드 실행이 꺼져 있기 때문입니다.
  • 자료조사 연구원이 "확인할 수 없다"고 합니다. 쓸 검색 도구가 없을 때 지어내지 않고 이렇게 답하도록 되어 있습니다. MCP 탭에서 검색 도구가 붙어 있는지 보세요. Ollama를 쓰면 웹 검색은 쓰이지 않습니다.
  • 메모를 검색했더니 엉뚱한 것도 나옵니다. 낱말 하나라도 맞으면 걸리는 방식입니다.
  • 연구원 지침을 저장했는데 진행 중인 연구에는 반영이 안 됩니다. 다음에 일을 맡길 때부터 적용됩니다.
관리자에게 알릴 때어느 탭에서, 무엇을 눌렀고, 화면에 뜬 문구가 무엇인지 그대로 적어 보내 주세요. 가능하면 연구 진행의 해당 항목을 펼친 화면도 함께 주세요.
