# 프로그램 사용 설명서

이 문서는 앱을 **설치하고 켜고 운영하는 사람**을 위한 것이다. 앱을 열어 쓰기만 하는 사람은 [getting-started.html](getting-started.html)을 본다. 구조가 궁금하면 [시스템 아키텍처](system-architecture.md)를 본다.

## 1. 설치 가이드

### 1.1 환경 요구사항

| 항목 | 요구 |
|------|------|
| Python | 3.9 이상. **추가 패키지는 필요 없다** |
| OS | Windows 11 / Ubuntu |
| 모델 | OpenRouter 계정과 API 키, 또는 도구 호출을 지원하는 모델을 서빙하는 Ollama |
| 네트워크 | OpenRouter 또는 Ollama, 쓰려는 MCP 서버에 접근 가능해야 함 |
| 브라우저 | 최신 Chrome · Edge · Firefox |

### 1.2 내려받기

```bash
git clone <저장소 주소> CommonAgents
cd CommonAgents
```

### 1.3 설정 파일 만들기

Windows (PowerShell):

```powershell
Copy-Item .env.example .env
```

Ubuntu:

```bash
cp .env.example .env
```

## 2. 초기 설정 (`.env`)

`.env`는 앱 폴더에 두며 git에 올라가지 않는다. **키 값은 화면·로그·오류 메시지에 나오지 않는다. 직접 열어 확인하는 것도 가급적 피한다.**

| 변수 | 설명 | 기본값 |
|------|------|--------|
| `OPENROUTER_API_KEY` | OpenRouter 키. OpenRouter를 쓸 때 필수 | (비어 있음) |
| `OPENROUTER_MODEL` | 처음 쓸 모델 이름. 화면에서 바꾸면 `state/llm_settings.json`이 우선 | `openai/gpt-4o-mini` |
| `OPENROUTER_CONTEXT_WINDOW_TOKENS` | 계기판이 쓰는 최대 컨텍스트 크기 | `128000` |
| `APP_TRUSTED_ORIGINS` | 공개 주소(프록시 뒤). 쉼표로 여러 개 | (없음) |
| `APP_ACCESS_TOKEN` | 공개 주소로 접속할 때 Basic 인증 비밀번호 | (없음) |

- `APP_TRUSTED_ORIGINS`와 `APP_ACCESS_TOKEN`은 **시작할 때 한 번만 읽는다.** 바꾸면 재시작한다.
- 토큰 없이 공개 주소를 등록하면 그 주소로의 접속은 전부 거부된다.
- Ollama만 쓴다면 키는 비워도 된다. 다만 `run.bat`은 `.env` 파일이 없으면 종료하므로 파일 자체는 만들어 둔다. `python app.py`로 직접 켜면 이 검사가 없다.
- 데이터베이스 마이그레이션은 없다. `state/`는 처음 쓸 때 자동으로 만들어진다.

## 3. 실행 방법

### 3.1 개발·개인 PC

| 환경 | 명령 |
|------|------|
| Windows | `.\run.bat` |
| Ubuntu | `./run.sh` |
| 점검 포함(권장) | Windows `scripts\dev\start-dev.bat` · Ubuntu `./scripts/dev/start-dev.sh` |
| 직접 실행 | `python app.py` (Windows는 `py app.py`) |

- 직접 실행하면 환경변수 `PYTHONUTF8=1`을 스스로 설정해야 한다. UI와 데이터가 한국어라서 필요하다.
- 켜지면 브라우저가 `http://127.0.0.1:8770/`을 자동으로 연다. 열지 않으려면 `AGENT_LAB_NO_BROWSER=1`을 설정한다.
- 연구원 서버(`:8771`, `:8772`)는 **연구를 시작하거나 에이전트 탭에서 [시작]을 누를 때** 뜬다. 단독 실행도 가능하다: `python agents/research_agent.py`, `python agents/experiment_agent.py`.
- 종료는 터미널에서 `Ctrl+C` 또는 창 닫기. 연구원 프로세스도 함께 종료된다.

### 3.2 서버(Ubuntu) — systemd + Nginx

```bash
sudo ./scripts/deploy/install-service.sh              # 서비스 등록·시작
sudo ./scripts/deploy/nginx-site.sh agent.example.com # Nginx 프록시
# .env 에 APP_TRUSTED_ORIGINS=https://agent.example.com 와 APP_ACCESS_TOKEN=<긴 비밀번호> 추가
sudo systemctl restart common-agent
sudo certbot --nginx -d agent.example.com             # HTTPS
```

갱신은 `./scripts/deploy/deploy.sh`(작업 트리가 깨끗해야 한다. `git pull --ff-only` → 문법 점검 → 재시작).

### 3.3 환경별 차이

| 항목 | 개발 | 서버 |
|------|------|------|
| 접속 | `http://127.0.0.1:8770/` | `https://공개주소/` (Basic 인증) |
| 인증 | 없음 | 비밀번호 = `APP_ACCESS_TOKEN` |
| 프로세스 관리 | 터미널 | systemd (`Restart=on-failure`) |
| 로그 | 터미널 | `journalctl -u common-agent -f` |
| Ollama 주소 | `localhost` 가능 | 앱 서버에서 접근 가능한 주소 |

## 4. 주요 기능 사용법

화면 상단 탭은 **도구 · MCP · 에이전트**이다.

### 4.1 도구 탭

```text
┌ 모델 연결 ─────────────┐  ┌ Context Window ──────┐
│ 제공자 / 모델 이름       │  │ 전체 사용량 + 항목별 비중 │
│ (Ollama면 API 주소)    │  ├ 모델에 제공되는 도구 ──┤
├ 역할 지시문 ────────────┤  │ memo_tool_1 …         │
│ 시스템 프롬프트 [저장]    │  └──────────────────────┘
├ 대화 ──────────────────┤
│ 이전 대화 / 도구 호출 내역 │
│ [요청 입력] [보내기]      │
└────────────────────────┘
```

- **모델 연결**: 제공자를 고르고 모델 이름을 적은 뒤 [설정 저장]. Ollama는 도구 호출을 지원하는 모델이어야 하며 웹 검색은 쓰이지 않는다.
- **역할 지시문**: 시스템 프롬프트를 고친다. [초기화]로 기본값 복귀. 기본 프롬프트는 "처리 가능 여부가 불확실하면 답하기 전에 관련 도구를 먼저 호출해 본다"는 규칙을 포함한다(도구를 부르지 않고 "할 수 없다"고 답하는 것을 줄이기 위해서다).
- **스킬**: 오른쪽 아래 카드. 스킬은 모델이 필요할 때 읽는 지침 글이다. [스킬 추가]나 목록의 스킬을 눌러 팝업에서 이름(영문 소문자·숫자·`-`·`_`), 설명, 쓸 도구, 지침을 쓰고 [저장]한다. 저장하면 다음 요청부터 적용되며 앱을 다시 켤 필요가 없다. 팝업 위의 [SKILL.md를 붙여 넣어 채우기]로 Claude Code의 SKILL.md를 그대로 붙여 넣을 수도 있다(설명은 300자로 줄고, `bun`·Artifact 같은 Claude Code 전용 내용이 있으면 경고한다). **설명이 가장 중요하다.** 모델은 설명만 보고 스킬을 읽을지 정한다. 스킬은 코드를 실행하지 않는다.
- **HTML 문서**: "결과를 HTML로 만들어줘"라고 하면 기본 제공 `html` 스킬이 문서를 만든다. 답변에 문서가 미리보기로 나오고 위쪽 [다운로드]로 파일을 받는다. 아래 [소스 보기]로 HTML 소스를 볼 수 있다. 미리보기에서는 스크립트가 실행되지 않고 외부 이미지·글꼴은 쓰이지 않는다. 디자인은 `ledger`(남색·금색)와 `dossier`(녹색·주황) 두 가지다.
- **대화**: 요청을 보내면 모델이 도구를 골라 호출하고, 호출 내역이 아래에 펼쳐진다. 대화는 `state/chat_history.json`에 저장되어 다음 요청에 이어진다(최근 30턴). [대화 초기화]로 비운다.
- 내장 도구는 메모 파일 하나를 다루는 `memo_tool_1`(검색) · `2`(저장) · `3`(삭제) · `4`(문장 일부 수정)이다.

### 4.2 MCP 탭

- **MCP 서버**: 목록의 서버를 켜고 끈다. 켜면 `mcp_config.json`에 기록되고 즉시 연결을 시도한다. 한 서버가 실패해도 나머지는 쓰인다. 실패 문구는 화면 위쪽 오류 띠에 나온다.
- **원격 서버 추가**: 서버 이름과 주소(Streamable HTTP)를 넣고 [추가]. 키가 필요하면 주소에 `${API_KEY}`처럼 이름만 적고 값은 `.env`에 둔다. 인증 헤더가 필요하면 [추가 헤더]에 한 줄에 하나씩 `이름: 값`으로 적는다(예: `Authorization: Bearer ${API_KEY}`). 인증값을 도구 인자(`api_key` 등)로 받는 서버는 [고정 인자]에 `api_key: ${변수명}`으로 적는다. 모든 도구 호출에 자동으로 들어가고 모델에게는 보이지 않는다.
- **JSON으로 추가**: Claude Desktop 식 `{"mcpServers": {"이름": {"url": "...", "headers": {...}}}}`를 [JSON으로 추가] 칸에 그대로 붙여 넣는다. 여러 서버를 한 번에 넣을 수 있고, 일부가 실패하면 성공한 것만 추가하고 이유를 알려 준다. 명령을 실행하는 서버(`command`)는 받지 않는다. JSON에 실제 키를 적으면 `state/mcp_custom.json`에 평문으로 저장되므로 `${변수명}`을 쓴다.
- **사용 가능한 도구 / 제외된 도구**: 도구 단위로 이 앱에서 쓰지 않도록 뺄 수 있다(복원 가능).
- 직접 추가한 서버만 삭제할 수 있다.

### 4.3 에이전트 탭

```text
┌ 에이전트 상태 ─┐  ┌ 연구 요청 ─────────────────┐
│ 연구책임자       │  │ 입력창 [연구 시작][중지]            │
│ 자료조사 연구원   │  ├ 연구원 지침 ───────────────┤
│ 실험수행 연구원   │  │ [지침 편집] → 팝업               │
│ [모두 시작/종료] │  ├ 이어서 물어보기 (연구 후 표시) ─┤
├ 연구 자료 ─────┤  ├ 연구 진행: 지시 · 보고 · 작업 ──┤
│ 파일 추가        │  └────────────────────────────┘
│ 역할 연결 상태    │
└────────────────┘
```

- **연구 요청**: 질문을 적고 [연구 시작]. 입력 칸은 처음에 비어 있다(예시 질문을 미리 채우지 않는다). 꺼져 있는 연구원은 자동으로 뜬다. 진행 중에는 지시와 보고가 실시간으로 쌓이고, [중지]는 현재 맡겨 둔 일이 끝나는 대로 멈춘다.
- **이어서 물어보기**: 연구가 끝나면 나타난다. 앞선 연구의 문맥을 이어받아 조건만 바꿔 다시 계산시킬 수 있다. [새 연구]로 문맥을 지운다.
- **연구 자료**: CSV · TXT · JSON을 파일당 2MB까지 올린다. 같은 이름이면 덮어쓸지 묻고, 삭제는 되돌릴 수 없다. 실험수행 연구원만 이 파일을 읽는다.
- **연구원 지침**: [지침 편집]을 누르면 팝업이 열린다. 연구원을 고르고 지침을 고쳐 [저장]. 저장하지 않고 닫아도(닫기 버튼, 배경 클릭, Esc) 쓰던 글은 남는다. **다음 위임부터** 적용되며 연구원을 다시 띄울 필요가 없다. [기본값으로]로 복귀. 지침에는 "실행하지 않은 수치를 만들지 않는다", "사업 가정은 자료 파일의 값만 쓴다", "추진 여부를 판단하지 않는다" 같은 앱이 의존하는 규칙이 들어 있으니 줄이거나 지울 때 주의한다.

## 5. 관리자 기능

| 하고 싶은 일 | 방법 |
|--------------|------|
| 모델 바꾸기 | 도구 탭 > 모델 연결 |
| 연구원 프로세스 상태 보기·재시작 | 에이전트 탭 > 에이전트 상태 |
| 연구원 지침 바꾸기 | 에이전트 탭 > 연구원 지침 |
| 연구 자료 관리 | 에이전트 탭 > 연구 자료 |
| MCP 서버·도구 관리 | MCP 탭 |
| 스킬 추가·수정 | 도구 탭 > 스킬 |
| 메모를 처음 상태로 | 앱을 끈 뒤 `data/notes.json` 삭제 후 재시작 (seed에서 다시 만들어짐) |
| 모든 화면 설정 초기화 | 앱을 끈 뒤 `state/` 삭제 |
| 외부 공개 | §3.2 |

사용자 계정·권한 관리 기능은 없다. 접속 통제는 §3.2의 신뢰 origin + 토큰이 전부다.

## 6. 운영 가이드

### 6.1 백업

| 대상 | 내용 |
|------|------|
| `state/` | 설정·대화·지침·사용자 추가 MCP 서버·만든 HTML 문서(`state/outputs/`) |
| `skills/` | 스킬(SKILL.md). git이 추적한다 |
| `data/research/` | 연구 자료 (저장소에는 샘플 `line_transition.csv`만 추적됨) |
| `data/notes.json` | 메모 작업본 |
| `.env` | 키. 별도로 안전하게 보관 |

앱이 꺼진 상태에서 복사하는 것이 가장 안전하다. 모델 설정·대화 기록·지침은 임시 파일을 거쳐 교체하므로 켜 둔 채 복사해도 대체로 깨지지 않는다.

### 6.2 모니터링과 로그

- 앱 자체 로그는 거의 없다 (`log_message`를 비워 콘솔을 조용하게 둔다). 시작할 때 도구 목록과 MCP 연결 실패만 출력된다.
- 서버에서는 `journalctl -u common-agent -f`.
- 연구의 상세 기록(모델과 주고받은 원문, 도구 호출)은 화면의 **연구 진행** 영역에서 펼쳐 본다. 연구가 끝나면 메모리에서 사라지니 필요하면 그전에 확인한다.
- 포트 점검: `netstat -ano | findstr :8770` (Windows), `ss -ltnp | grep 877` (Ubuntu).

### 6.3 장애 대응

| 증상 | 원인 | 조치 |
|------|------|------|
| `run.bat`이 곧바로 닫힘 | `.env` 없음 | `.env.example`을 복사 |
| 새 기능이 안 보임 | 옛 서버가 포트를 잡고 있음. Windows는 같은 포트에 둘이 붙을 수 있어 옛 서버가 요청을 받음 | 옛 프로세스를 종료하고 다시 켠다 |
| "연구원을 띄우지 못했습니다" | 8771/8772를 다른 프로세스가 사용, 또는 Python 오류 | 포트 확인. 화면의 메시지 끝에 연구원의 오류 마지막 부분이 붙는다 |
| 연구원 프로세스가 남음 | 창을 강제로 닫아 정리가 안 됨 | 다음 기동 때 자동 정리(`cleanup_stale`). 안 되면 8771/8772 프로세스를 수동 종료 |
| "응답을 받지 못했습니다" | 모델 API 오류 | 키·잔액·모델 이름 확인 |
| "잠시 후 다시 시도해 주세요 (약 1분)" | 429 한도 | 1분 뒤 재시도 |
| 설정을 저장했는데 OpenRouter로 돌아감 | `llm_settings.json`에 BOM이 붙어 읽기 실패 | BOM 없는 UTF-8로 다시 저장하거나 화면에서 다시 저장 |
| 공개 주소로 접속하면 403 | Host 불일치 또는 토큰 없음 | `nginx-site.sh`의 Host 전달, `.env` 두 값, 재시작 확인 |
| "디스크에 저장하지 못했습니다" | `state/` 쓰기 불가 | 권한·영구 저장소 확인 |

## 7. 업데이트 · 마이그레이션

1. (서버) `./scripts/deploy/deploy.sh` 한 번이면 된다.
2. (개인 PC) 앱을 끄고 `git pull` 후 다시 켠다.
3. 스키마 마이그레이션이 없다. 새 버전은 없는 키를 기본값으로 읽는다.
4. 브라우저가 옛 화면을 들고 있으면 강력 새로 고침(`Ctrl+F5`). 정적 파일은 `no-store`로 보내지만 `?v=` 값이 바뀌어도 탭이 열려 있으면 이전 스크립트가 남는다.
5. 되돌리기: `git log`로 이전 커밋을 확인해 `git reset --hard <커밋>` 후 재시작. `state/`는 git 밖이라 영향이 없다.

## 8. 하지 않는 것

- 코드 실행(`run_python`)은 막혀 있다. 실험수행 연구원이 숫자를 직접 계산하지 못하고, 필요한 코드와 입력을 보고하는 데 그친다. OS 수준 격리 실행기가 생기기 전에는 켜지 않는다.
- 사용자 계정·다중 사용자·동시 접속 분리는 없다.
