API 설계 문서

Common Agent는 브라우저 화면과 JSON API를 한 프로세스(app.py, 기본 http://127.0.0.1:8770/)에서 제공하는 로컬 웹 앱이다. Python 표준 라이브러리(http.server)만 쓰며 외부 프레임워크가 없다. 연구원 두 명은 별도 프로세스로 뜨고, 연구책임자(본체)만 그들의 주소를 안다.

관련 문서: 시스템 아키텍처 · API 사용자 가이드 · 데이터 저장소 설계

1.1 요청 검증 (lab/http_security.py)

GET과 POST 모두 먼저 validate_local_host를 통과해야 한다. POST는 이어서 validate_json_post의 나머지 검사를 받는다.

순서검사실패 시
1Host 헤더가 127.0.0.1:포트 · localhost:포트 · 신뢰 origin의 호스트 중 하나403 요청한 호스트를 허용하지 않습니다.
2신뢰 origin으로 들어온 요청은 HTTP Basic 인증 (비밀번호 = APP_ACCESS_TOKEN, 사용자명은 무엇이든)토큰 미설정 403, 인증 없음/틀림 401 + WWW-Authenticate
3Origin이 http://127.0.0.1:포트 · http://localhost:포트 · 신뢰 origin 중 하나 (Origin이 없으면 거절)403 허용되지 않은 요청 출처입니다.
4Sec-Fetch-Site가 cross-site가 아님403 교차 출처 요청을 허용하지 않습니다.
5Content-Type이 application/json415 JSON 요청만 허용됩니다.
6Content-Length가 유효하고 상한 이하400 / 413 보낸 내용이 너무 큽니다.
7본문이 UTF-8 JSON400 요청을 읽지 못했습니다.
  • 루프백(127.0.0.1/localhost) 접속은 인증하지 않는다. Host/Origin 검사가 방어선이다.
  • 신뢰 origin은 .env의 APP_TRUSTED_ORIGINS(쉼표 구분)로 지정하며, 시작할 때 한 번만 읽는다. 바꾸려면 재시작.
  • 연구원 서버는 browser_origins=()로 호출해 브라우저가 보낸 Origin 헤더가 있으면 거절한다. 본체 프로세스만 호출할 수 있다.

1.2 락(LOCK) 규칙

모든 POST는 전역 LOCK 하나로 줄 세워 처리한다. /api/research는 연구가 끝날 때까지(수 분) 이 락을 쥔다. 따라서:

  • 연구 중에도 응답해야 하는 POST는 lock=False로 등록한다: /api/research/stop, /api/agents/prompt, /api/agents/prompt/reset.
  • 연구 중에도 읽어야 하는 GET은 락을 잡지 않는다: /api/context, /api/agents, /api/research/progress, /api/output. (/api/state만 락을 잡는다.)

3.4 MCP

  • /api/mcp/toggle: 카탈로그에 있는 서버만 켜고 끈다. 결과를 mcp_config.json에 쓰고 연결을 초기화한다.
  • /api/mcp/add: 이름 40자 이하, 예약어 내장·위임·스킬·알 수 없음 불가, 중복 불가, 주소는 http:// 또는 https://이며 공백 불가. headers는 이름: 값 줄 문자열 또는 {이름: 값} 객체이며 20개, 값 2,000자 이하, 제어 문자 불가, Host·Content-Type·Accept·Mcp-* 등 예약 헤더 불가. 키는 주소와 헤더 값에 ${변수명}으로 적으면 연결 시점에 .env에서 채운다. 추가 즉시 연결한다. fixed_args는 이름: 값 줄 문자열 또는 객체(20개 이하)이며, 인증값을 도구 인자로 받는 서버용이다. 그 서버의 모든 tools/call 인자에 자동으로 합쳐지고(모델이 같은 이름을 넣어도 고정값 우선) 모델에게 주는 도구 스키마에서는 빠진다. 화면 목록에는 헤더·고정 인자의 이름만 보이고 값은 노출하지 않는다. 서버가 오류 글에 받은 인자를 되돌려 줘도 고정 인자 값은 ***로 가려 모델과 대화 기록에 넘긴다(4자 이상인 값).
  • /api/mcp/add_json: Claude Desktop 식 {"mcpServers": {이름: {url, headers?, fixed_args?}}}(또는 {이름: {...}}만)를 붙여 넣어 한꺼번에 추가한다. 한 번에 20개까지. **원격(url) 서버만** 받고 command가 있는 항목은 이유와 함께 거절한다(화면에서 명령 실행 서버를 추가하는 것은 막는다). 항목마다 /api/mcp/add와 같은 검사를 거치며, 일부만 실패하면 성공한 서버는 추가하고 실패한 것은 problems에 이름: 이유로 돌려준다. 모두 실패하면 ok: false.
  • /api/mcp/remove: 직접 추가한 서버만 삭제 가능(state/mcp_custom.json). 기본 카탈로그 서버는 연결만 끊을 수 있다.
  • /api/mcp/tool/remove·restore: 서버 단위가 아닌 도구 단위로 제외/복원 (state/disabled_mcp_tools.json).

3.5 스킬

  • /api/skills/save: 스킬 한 개를 추가하거나 고친다. 이름은 ^[a-z0-9][a-z0-9_-]{0,39}$(폴더 이름으로 쓰므로 경로를 우회할 수 없다), 설명 1~300자, 지침 1~20,000자, tools는 lab/skills.py의 SKILL_TOOLS에 있는 이름만(현재 render_html). 스킬은 30개까지. 같은 이름이 있으면 그 폴더의 SKILL.md를 덮어쓴다. 저장하면 다음 요청부터 모델에게 보이며 앱을 다시 켤 필요가 없다. 틀리면 {ok: false, message}.
  • /api/skills/get: 스킬 한 개의 본문까지 돌려준다. /api/state의 skills 목록에는 이름·설명·도구만 있고 본문은 없다(상태를 자주 읽는데 스킬마다 최대 2만 자가 실리는 것을 피하려고). 편집 팝업이 열릴 때 부른다.
  • /api/skills/delete: skills/<폴더>/SKILL.md를 지우고 폴더가 비면 폴더도 지운다. 되돌릴 수 없다.
  • 스킬은 코드를 실행하지 않는다. 글(지침)과 코드에 등록된 도구 이름만 담는다.
  • SKILL.md는 80KB까지 읽는다(지침 2만 자 + 머리말, 한글은 글자당 3바이트). 넘거나 이름 형식이 틀려 읽지 못한 스킬은 목록에서 빠지되 화면 위쪽 오류 띠에 ○○ 스킬이 너무 커서 건너뛰었습니다 같은 안내가 나온다.

4. 연구원 서버 (:8771 / :8772)

agents/_serve.py가 두 연구원을 같은 코드로 띄운다. 달라지는 것은 역할 지침과 도구뿐이다.

메서드·경로설명
GET /info{ok, role, label, pid, port, web_search, tools, errors}
POST /task본문 {instruction} → {ok, result, calls, searches, tokens, elapsed, steps, trace}
  • 기동하면 표준 출력에 READY <role> <port> <pid> 한 줄을 쓴다. 부모가 이 줄로 기동을 확인하므로 형식을 바꾸면 안 된다.
  • POST /task는 호출 때마다 roles.prompt_for(role)로 지침을 읽는다 → 화면에서 고친 지침이 재시작 없이 반영된다.
  • trace는 연구원이 모델과 주고받은 요청·응답, 실행한 도구 호출의 순서 기록이다.
  • 본체의 _send()가 호출하며 제한 시간은 600초다.

MCP(HTTP)Streamable HTTP요청당 30초프로토콜 버전 2025-06-18

모델 요청은 temperature 0.0, stream: false다. 웹 검색이 켜진 연구원(자료조사)은 OpenRouter일 때만 plugins: [{"id":"web"}]를 붙인다. engine은 지정하지 않는다. OpenRouter가 모델이 내장 검색을 지원하면 그것을, 아니면 Exa를 고른다("native"로 못박으면 gpt-4o-mini 같은 모델에서 HTTP 404 The requested model does not support native web search가 난다). Ollama에는 웹 검색 플러그인이 없다.

6. 인증·비율 제한·페이지네이션

  • 인증: 루프백은 없음. 신뢰 origin은 Basic 인증(APP_ACCESS_TOKEN). 토큰이 없으면 신뢰 origin 접속 자체를 거부한다.
  • 비율 제한: 앱 자체에는 없다. 모델 쪽 429만 처리한다.
  • 페이지네이션: 없다. 대화 기록은 최근 30턴(CHAT_MAX_TURNS)만 유지한다.
  • 에러 응답 형식: 보안 검사 실패는 {"ok": false, "message": "..."} + 4xx(GET은 text/plain). 업무 실패는 HTTP 200 + ok: false. 처리기가 예상 밖의 예외를 내도(값 형식이 틀린 요청 등) 연결을 끊지 않고 HTTP 200 + {"ok": false, "message": "요청 값의 형식이 올바르지 않거나 처리 중 오류가 났습니다."}를 돌려주며, 원인은 서버 콘솔에 남는다.

1.3 첫 호출

GET은 헤더 없이 된다.

curl http://127.0.0.1:8770/api/agents

POST는 반드시 세 가지를 지켜야 한다. 하나라도 빠지면 거절된다.

  1. Content-Type: application/json
  2. Origin: http://127.0.0.1:8770 (브라우저가 아닌 클라이언트는 직접 붙여야 한다)
  3. Host가 127.0.0.1:8770 또는 localhost:8770 (curl이 URL에서 자동으로 채운다)
curl -X POST http://127.0.0.1:8770/api/chat \
  -H "Content-Type: application/json" \
  -H "Origin: http://127.0.0.1:8770" \
  -d '{"message": "회의 메모 찾아줘"}'

2. 언어별 예제

2.1 Python (urllib, 표준 라이브러리)

import json
import urllib.request

BASE = "http://127.0.0.1:8770"

def post(path, payload):
    req = urllib.request.Request(
        BASE + path,
        data=json.dumps(payload, ensure_ascii=False).encode("utf-8"),
        headers={"Content-Type": "application/json", "Origin": BASE},
        method="POST",
    )
    with urllib.request.urlopen(req, timeout=900) as r:
        return json.loads(r.read().decode("utf-8"))

print(post("/api/chat", {"message": "회의 메모 찾아줘"})["answer"])

5. FAQ / 트러블슈팅

POST만 403이 난다. Origin 헤더를 붙였는지 확인한다. curl은 기본으로 붙이지 않는다.

연구 요청이 끝나지 않는다. 정상일 수 있다. 연구원 한 명의 호출이 최대 600초까지 걸린다. /api/research/progress의 log가 늘어나고 있다면 진행 중이다.

연구 중에 다른 POST가 멈춰 있다. /api/research가 전역 락을 쥐고 있기 때문이다. 연구가 끝나거나 /api/research/stop으로 멈추면 풀린다. /api/agents/prompt와 /api/research/stop은 예외로 락 없이 응답한다.

**.env를 고쳤는데 반영되지 않는다.** APP_TRUSTED_ORIGINS와 APP_ACCESS_TOKEN은 시작할 때 한 번만 읽는다. 재시작한다.

포트가 이미 사용 중이라고 나온다. Windows는 같은 포트에 서버 둘이 붙을 수 있어, 옛 서버가 조용히 요청을 받는 일이 있다. 켜기 전에 netstat -ano | findstr :8770으로 확인한다. scripts/dev/start-dev.bat이 이 점검을 해 준다.

서버 이름은 도구의 소속(source)이 된다. 예약어 내장·위임·스킬·알 수 없음은 쓸 수 없다. 기본 카탈로그와 이름이 겹치면 기본 카탈로그가 이긴다.

3.4-1 skills/<이름>/SKILL.md

---
name: html
description: 언제 쓰는지 한두 문장 (300자 이하)
tools: render_html
---

(모델이 따를 지침, 마크다운)

Claude Code의 SKILL.md와 같은 형식이다. tools에는 lab/skills.py의 SKILL_TOOLS에 있는 이름만 인정하고 나머지는 무시한다. 폴더 이름과 name이 다르면 name(소문자로 바꿈)이 스킬 이름이다. 파일은 30KB까지이며, 스킬 폴더의 다른 파일(파이썬 등)은 읽지 않는다. 이 폴더는 저장소에 들어 있고 state/와 달리 git이 추적한다.

3.4-2 state/outputs/<id>.html

render_html이 만든 완성된 HTML 문서다. id는 12자리 16진수. 모든 글을 이스케이프해 만든 파일이라 내려받아 열어도 스크립트가 없다. 50개를 넘으면 오래된 것부터 지운다. 대화 기록에는 [[html:<id>]] 표시 줄만 남고 문서 본문은 들어가지 않는다.

{ "mcpServers": { "국가법령": { "url": "https://mcp.gomdori.app/law" } } }

UML 시퀀스 다이어그램

핵심 흐름을 시나리오별로 정리했다. 구조는 시스템 아키텍처, 경로 명세는 API 설계를 본다.

1. 요청 검증 · 인증 (모든 요청 공통)

이 앱에는 사용자 계정이 없다. 로그인 대신 Host/Origin 검사 + 외부 접속 시 Basic 인증이 인증 역할을 한다.

sequenceDiagram
    participant C as 클라이언트
    participant H as Handler
    participant S as http_security

    C->>H: 요청 (Host, Origin, Authorization)
    H->>S: validate_local_host
    alt Host가 허용 목록에 없음
        S-->>H: RequestRejected 403
        H-->>C: 403 요청한 호스트를 허용하지 않습니다
    else 신뢰 origin으로 들어옴
        alt APP_ACCESS_TOKEN 미설정
            S-->>H: RequestRejected 403
            H-->>C: 403 외부 접속에는 토큰 설정이 필요합니다
        else Authorization 없음 또는 비밀번호 불일치
            S-->>H: RequestRejected 401
            H-->>C: 401 + WWW-Authenticate Basic
        else 비밀번호 일치
            S-->>H: 통과
        end
    else 루프백 접속
        S-->>H: 통과 (인증 없음)
    end
    Note over H,S: POST는 이어서 Origin, Sec-Fetch-Site, Content-Type, 본문 크기를 검사한다

모델은 어떤 도구를 부를지 결정만 하고, 실행은 runner.run()이 한다.

3.1 설계 원칙

  • 모델은 결정만, 실행은 앱이. 모든 도구는 {name, description, parameters, source, call} 딕셔너리이며 예외는 {"오류": ...}로 모델에게 돌려줘 재시도하게 한다.
  • 역할 경계는 지침이 아니라 코드로. 연구책임자는 위임 도구 둘만, 자료조사는 MCP·웹 검색만, 실험수행은 read_data_file만 받는다. 연구원끼리는 서로를 부를 수단이 없다.
  • 실패해도 앱은 죽지 않는다. 깨진 상태 파일은 빈 값으로, 연결 실패한 MCP 서버는 건너뛰고 나머지를 쓴다.
  • 키는 밖으로 내지 않는다. OPENROUTER_API_KEY는 화면·로그·오류 메시지·상태 응답 어디에도 실리지 않는다.

  • 설정: 화면 → 각 /api/... → state/ 파일. 일부는 읽을 때마다 파일을 다시 본다(연구원 지침, 모델 설정은 수정 시각 비교).

6. 동시성 모델

graph TD
    P1["POST 요청 A"] --> L{"전역 LOCK"}
    P2["POST 요청 B"] --> L
    L --> H1["한 번에 하나만 실행"]
    G1["GET 상태 읽기: LOCK 사용"] --> L

  • 본체는 요청마다 스레드를 쓰지만 대부분의 POST는 하나의 LOCK으로 직렬화된다. 상태 파일 쓰기가 겹치지 않게 하는 가장 단순한 방법이다.

  • 중지는 협조적이다. 다음 단계를 시작하지 않을 뿐, 이미 보낸 연구원 호출이나 모델 호출은 끊지 못한다.

4. 주요 기능 사용법

화면 상단 탭은 도구 · MCP · 에이전트이다.

4.1 도구 탭

┌ 모델 연결 ─────────────┐  ┌ Context Window ──────┐
│ 제공자 / 모델 이름       │  │ 전체 사용량 + 항목별 비중 │
│ (Ollama면 API 주소)    │  ├ 모델에 제공되는 도구 ──┤
├ 역할 지시문 ────────────┤  │ memo_tool_1 …         │
│ 시스템 프롬프트 [저장]    │  └──────────────────────┘
├ 대화 ──────────────────┤
│ 이전 대화 / 도구 호출 내역 │
│ [요청 입력] [보내기]      │
└────────────────────────┘
  • 모델 연결: 제공자를 고르고 모델 이름을 적은 뒤 [설정 저장]. Ollama는 도구 호출을 지원하는 모델이어야 하며 웹 검색은 쓰이지 않는다.
  • 역할 지시문: 시스템 프롬프트를 고친다. [초기화]로 기본값 복귀. 기본 프롬프트는 "처리 가능 여부가 불확실하면 답하기 전에 관련 도구를 먼저 호출해 본다"는 규칙을 포함한다(도구를 부르지 않고 "할 수 없다"고 답하는 것을 줄이기 위해서다).
  • 스킬: 오른쪽 아래 카드. 스킬은 모델이 필요할 때 읽는 지침 글이다. [스킬 추가]나 목록의 스킬을 눌러 팝업에서 이름(영문 소문자·숫자·-·_), 설명, 쓸 도구, 지침을 쓰고 [저장]한다. 저장하면 다음 요청부터 적용되며 앱을 다시 켤 필요가 없다. 파일이 80KB를 넘거나 이름이 올바르지 않아 읽지 못한 스킬은 목록에서 빠지고 화면 위쪽 오류 띠에 이유가 나온다. 팝업 위의 [SKILL.md를 붙여 넣어 채우기]로 Claude Code의 SKILL.md를 그대로 붙여 넣을 수도 있다(설명은 300자로 줄고, bun·Artifact 같은 Claude Code 전용 내용이 있으면 경고한다). 설명이 가장 중요하다. 모델은 설명만 보고 스킬을 읽을지 정한다. 스킬은 코드를 실행하지 않는다.
  • HTML 문서: "결과를 HTML로 만들어줘"라고 하면 기본 제공 html 스킬이 문서를 만든다. 답변에 문서가 미리보기로 나오고 위쪽 [다운로드]로 파일을 받는다. 아래 [소스 보기]로 HTML 소스를 볼 수 있다. 미리보기에서는 스크립트가 실행되지 않고 외부 이미지·글꼴은 쓰이지 않는다. 디자인은 ledger(남색·금색)와 dossier(녹색·주황) 두 가지다.
  • 대화: 요청을 보내면 모델이 도구를 골라 호출하고, 호출 내역이 아래에 펼쳐진다. 대화는 state/chat_history.json에 저장되어 다음 요청에 이어진다(최근 30턴). [대화 초기화]로 비운다.
  • 내장 도구는 메모 파일 하나를 다루는 memo_tool_1(검색) · 2(저장) · 3(삭제) · 4(문장 일부 수정)이다.

4.2 MCP 탭

  • MCP 서버: 목록의 서버를 켜고 끈다. 켜면 mcp_config.json에 기록되고 즉시 연결을 시도한다. 한 서버가 실패해도 나머지는 쓰인다. 실패 문구는 화면 위쪽 오류 띠에 나온다.
  • 원격 서버 추가: 서버 이름과 주소(Streamable HTTP)를 넣고 [추가]. 키가 필요하면 주소에 ${API_KEY}처럼 이름만 적고 값은 .env에 둔다. 인증 헤더가 필요하면 [추가 헤더]에 한 줄에 하나씩 이름: 값으로 적는다(예: Authorization: Bearer ${API_KEY}). 인증값을 도구 인자(api_key 등)로 받는 서버는 [고정 인자]에 api_key: ${변수명}으로 적는다. 모든 도구 호출에 자동으로 들어가고 모델에게는 보이지 않는다.
  • JSON으로 추가: Claude Desktop 식 {"mcpServers": {"이름": {"url": "...", "headers": {...}}}}를 [JSON으로 추가] 칸에 그대로 붙여 넣는다. 여러 서버를 한 번에 넣을 수 있고, 일부가 실패하면 성공한 것만 추가하고 이유를 알려 준다. 명령을 실행하는 서버(command)는 받지 않는다. JSON에 실제 키를 적으면 state/mcp_custom.json에 평문으로 저장되므로 ${변수명}을 쓴다.
  • 사용 가능한 도구 / 제외된 도구: 도구 단위로 이 앱에서 쓰지 않도록 뺄 수 있다(복원 가능).
  • 직접 추가한 서버만 삭제할 수 있다.

4.3 에이전트 탭

┌ 에이전트 상태 ─┐  ┌ 연구 요청 ─────────────────┐
│ 연구책임자       │  │ 입력창 [연구 시작][중지]            │
│ 자료조사 연구원   │  ├ 연구원 지침 ───────────────┤
│ 실험수행 연구원   │  │ [지침 편집] → 팝업               │
│ [모두 시작/종료] │  ├ 이어서 물어보기 (연구 후 표시) ─┤
├ 연구 자료 ─────┤  ├ 연구 진행: 지시 · 보고 · 작업 ──┤
│ 파일 추가        │  └────────────────────────────┘
│ 역할 연결 상태    │
└────────────────┘
  • 연구 요청: 질문을 적고 [연구 시작]. 입력 칸은 처음에 비어 있다(예시 질문을 미리 채우지 않는다). 꺼져 있는 연구원은 자동으로 뜬다. 진행 중에는 지시와 보고가 실시간으로 쌓이고, [중지]는 현재 맡겨 둔 일이 끝나는 대로 멈춘다.
  • 이어서 물어보기: 연구가 끝나면 나타난다. 앞선 연구의 문맥을 이어받아 조건만 바꿔 다시 계산시킬 수 있다. [새 연구]로 문맥을 지운다.
  • 연구 자료: CSV · TXT · JSON을 파일당 2MB까지 올린다. 같은 이름이면 덮어쓸지 묻고, 삭제는 되돌릴 수 없다. 실험수행 연구원만 이 파일을 읽는다.
  • 연구원 지침: [지침 편집]을 누르면 팝업이 열린다. 연구원을 고르고 지침을 고쳐 [저장]. 저장하지 않고 닫아도(닫기 버튼, 배경 클릭, Esc) 쓰던 글은 남는다. 다음 위임부터 적용되며 연구원을 다시 띄울 필요가 없다. [기본값으로]로 복귀. 지침에는 "실행하지 않은 수치를 만들지 않는다", "사업 가정은 자료 파일의 값만 쓴다", "추진 여부를 판단하지 않는다" 같은 앱이 의존하는 규칙이 들어 있으니 줄이거나 지울 때 주의한다.

7. 업데이트 · 마이그레이션

  1. (서버) ./scripts/deploy/deploy.sh 한 번이면 된다.
  2. (개인 PC) 앱을 끄고 git pull 후 다시 켠다.
  3. 스키마 마이그레이션이 없다. 새 버전은 없는 키를 기본값으로 읽는다.
  4. 브라우저가 옛 화면을 들고 있으면 강력 새로 고침(Ctrl+F5). 정적 파일은 no-store로 보내지만 ?v= 값이 바뀌어도 탭이 열려 있으면 이전 스크립트가 남는다.
  5. 되돌리기: git log로 이전 커밋을 확인해 git reset --hard <커밋> 후 재시작. state/는 git 밖이라 영향이 없다.

8. 하지 않는 것

  • 코드 실행(run_python)은 막혀 있다. 실험수행 연구원이 숫자를 직접 계산하지 못하고, 필요한 코드와 입력을 보고하는 데 그친다. OS 수준 격리 실행기가 생기기 전에는 켜지 않는다.
  • 사용자 계정·다중 사용자·동시 접속 분리는 없다.
